# 开放模型仓库（OpenModels）

OpenModels 是 AI 辅助制作、可追溯且可投入游戏使用的**美术资产仓库**。项目方向已经调整：

**唯一重点开发方向：使用正交三视图、极简 3D 参考与受控 AI 绘画生产 N 方向透明 PNG（伪 3D）**，面向《突袭》类正交 RTS 的成熟商业级画面。此前「由 AI 制作精细 3D 模型 + UV + 商业贴图」路线由于实际效果不达标，**停止作为继续投资和新任务的主线**。既有 3D 模型、工具、工程数据、源码和 GitHub Pages 3D 交互功能保留为历史成果、参考和必要的生产夹具；**禁止误解为删除 3D 区域或不能用极简 3D 辅助控制图**。

## 产品目标与核心规范

- **N 方向图生产流程**：[standards/n-direction-sprites.md](standards/n-direction-sprites.md)。
- **GitHub Pages 双入口／统一方向图播放架构**：[standards/sprite-viewer-architecture.md](standards/sprite-viewer-architecture.md)。
- **Agent 执行规程**：[AGENTS.md](AGENTS.md)。

### 核心生产路线

1. 参考授权可靠的正交三视图与工程尺寸。
2. 以纯 Python／无 GUI 工具制作**只保证基本外形、朝向和遮挡**的简化三维控制模型，无需精细贴图或 UV。
3. 固定真正的正交摄像机，围绕整车原点生成 64 个方向的轮廓、深度和部件分区控制图，支持按任意 16 个方向拼接 4×4 参考拼图。
4. 先用 4～8 个典型方向实际测试具备使用许可的受控 AI 绘图能力。**控制图生成成功不等于 ControlNet 推理成功，更不等于多方向美术一致**。
5. 生成并验收 **16 → 32 → 64 方向**。共用统一的 64 槽角度索引、固定正交尺度和画布、同一个像素锚点；只新增中间角度，保留已批准的图像不变。不得用复制/插值充当新独立方向。
6. 发布真实透明 RGBA PNG、manifest、可选游戏图集；用在线 360° 播放、64／128／256 像素 RTS 预览及商业美术审查验收。

**首个样品**是 1943 年早期 Tiger I（Tiger 131 参考）。第一阶段只制作车体、炮塔、炮管**不分离的一体版**，不做开火、炮口效果、后坐、履带动画或分体炮塔的组合爆炸；这属于下一阶段独立研究。

关键验收：商业级美术观感、轮廓与视角一致、细节跨角度稳定、没有虚假镜像标识、实际透明 PNG、统一锚点。工具运行通过不能代替成品验收。

## 网站：双入口，而非单一 3D 展厅

正式静态发布源保留 **`dev:/docs`**，目标地址 [OpenModels](https://siliconyc.github.io/OpenModels/)。

- **首页 `/`**：清楚呈现双入口，优先突出「多方向图／伪 3D」主线，同时保留「传统 3D（历史成果）」入口。不得默认跳入旧 3D 展厅。
- **`/sprites.html`**：主线方向图资产目录和**同一个通用 2D PNG 播放器**；支持 16／32／64 方向、旋转、透明查看、固定 pivot 及 64／128／256 像素预览。正式图片尚不存在时准确显示「未发布」，允许显式标记的程序化测试夹具用于基础设施验收，**不可把旧 GLB 当成伪 3D 成品**。
- **`/3d.html`**：保留原 Three.js GLB 查看器及全部既有功能；历史深链 `?model=...` 应继续可用。

网站数据驱动：所有型号共用 manifest schema、`000.png…063.png` 全局编号和一套播放器，不要为每个坦克建立重复页面。详见网站架构规范。**Pages 仅部署 `docs/` 内容，源模型目录 `models/` 下的 PNG 必须经过发布步骤拷贝至 `docs/assets/sprites/`**，不可在网站用相对路径直接假设仓库其它目录可访问。

先完成独立 Pages 基础设施任务，**不等待第一张正式 AI 伪 3D 图**；正式艺术品接入由原 #29 后续工作完成。N 方向图阶段总枢纽为 [Issue #22](https://github.com/SiliconYC/OpenModels/issues/22)。

## 目录结构与用途

以下是**按需建立的约定**，不是宣称文件或精灵图已经存在：

```text
OpenModels/
├── models/
│   └── vehicles/land/tiger-i/
│       ├── asset.yaml
│       ├── references/         # 三视图、尺寸、授权来源，共用
│       ├── source/             # 既有 3D 生成源码，保留
│       ├── textures/           # 既有 3D UV 贴图，保留
│       ├── export/             # 既有 GLB 文件，保留
│       └── sprites/            # 主线：2D N 方向生产与成品
│           ├── spec.json
│           ├── control/        # 轮廓、深度、分区等实际控制图
│           ├── generated/      # AI 原始候选及参数记录
│           ├── approved/       # 已验收的逐方向 RGBA PNG
│           ├── export/         # manifest、独立帧、可选图集
│           └── qa/             # 一致性报告及验收证据
├── tools/
│   └── sprites/               # 多资产通用方向生产和发布工具
├── docs/                      # Pages 双入口、2D 主播放器与 3D 保留区
│   └── assets/sprites/        # 仅发布经允许的静态方向图镜像
├── standards/
├── tests/
├── AGENTS.md
└── README.md
```

- `asset.yaml` 应分别记录 3D 历史和 sprites 生产状态，不覆盖或抹去旧记录。
- `references/` 有来源与版权信息；第三方图纸/贴图/模型及 AI 输入、再分发必须具有相应授权。
- `tools/sprites/` 是通用代码；特定资产配置、图像和质量记录留在该资产的 `sprites/`。
- 图集中的 4×4 **AI 控制拼图**只是创作/验收文件，不自动等于游戏最终运行用的纹理图集。

## 已有 3D 技术成果（归档保留）

过去完成过 Python/手写几何生成真实 GLB、UV 试验贴图和 Three.js 正交／透视展厅。保留既有模型、代码、源数据、`docs/models.json` 等，不删除、不编造其商业级美术质量；仍可用于基准测试、ControlNet 轮廓夹具、工程参考和展示。未经新授权**不要沿着旧路线继续大规模精细 3D 建模/UV/高品质 3D 贴图研发**。

3D 展厅的验收只需确保历史资产和控件确实可用；N 方向项目的终验是**真 PNG、真实方向一致性、商业美术质量**，不要求它能够以 GLB、UV 的形式交付。

## 开发与发布约束

- GitHub 仓库：`SiliconYC/OpenModels`；**开发及合并目标只用 `dev`，不得修改 `main`**。
- 每 Issue 独立开发分支和 PR、细粒度 Commit/Push、可断点续接；只在最新提交进行必要的验收，避免重复高频 CI。
- Agent 可使用云端 Python 和无头真实浏览器测试；不依赖用户 PC、桌面版 Codex、Blender（包括后台）或 Unity 编辑器。
- 模型、控制条件、PNG、manifest、网站实际资产必须真实存在。**禁止用概念图、伪透明底色、模拟深度图或旧 3D 模型冒充已完成的 2D 资产**。
- GitHub Pages 上线必须核对实际公网 URL、资源加载、交互与提交版本；测试夹具和未发布样品清楚标示。商业授权不明确时不可假称可商用。
