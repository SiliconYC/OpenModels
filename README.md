# 开放模型仓库（OpenModels）

AI 辅助设计与制作的可复用三维模型资产库，未来用于游戏、动画和其他可视化产品。

本仓库的目标不是展示漂亮但无法实现的概念图，而是**生产有真实几何、可编辑源文件、可追溯贴图和可实际交付的商业级模型资产**。

## 设计方向

- **商业化完成度**：造型、配色、比例、识别性和整体统一性必须达到成熟商业产品的标准；不把粗糙当成「独立风格」。
- **低多边形 + 高品质贴图**：以准确轮廓和主要机械体块为基础，把装甲接缝、编号、磨损等表面细节尽可能交给贴图；不堆砌无意义的几何。
- **面向小尺度显示**：优先以 RTS 中的小型单位为使用场景，同时保留必要的放大展示能力。不能只凭近景大图评价效果。
- **简化光照依赖**：优先研究无光照 / 自发光材质配合预绘制的风格化贴图；允许少量实时接地阴影。避免强烈烘焙方向高光与实时光照冲突。
- **可维护的批量生产**：优先采用参考模型改造、Blender 与 Python 自动化、标准化文件结构和可复现验收。修改现有资产通常优先于从零制作，但必须满足授权要求。
- **跨项目复用**：不绑定特定游戏引擎；以 Blender 源文件及通用导出格式为主，Unity 等引擎是验证和使用端。

首批重点研究坦克等刚性载具，后续可扩展汽车、飞机、舰船和其他模型。暂不为人物等需要复杂形变的角色预设统一生产工艺。

## 资产制作流程

### 1. 三视图

建立同一尺度和比例下的正面、侧面、顶部正交参考图。标明车头方向、各轴向、主要尺寸比例及重要旋转中心。

三视图是几何参考，不是可以替代建模的视觉海报；若来自 AI 绘图，必须核查三个视图之间的结构是否一致。

### 2. 低多边形模型

依据三视图建立真实、可编辑的简化三维网格。先保证整体轮廓、机械体块、位置和转动轴正确，再控制面数。面数目标按照最终显示尺寸确定，不能仅凭概念图声称具体三角面数量。

刚性载具优先拆成车体、炮塔、炮管、车轮或螺旋桨等对象，用层级和枢轴控制；无实际必要不引入骨骼、蒙皮和复杂物理系统。

### 3. 精美贴图

为**实际模型的 UV** 制作高质量、设计化的贴图，尽量用色彩、接缝、表面磨损和局部明暗表达细节。允许 AI 绘图辅助，但最终纹理必须准确映射模型，不能把单张漂亮的效果图冒充成贴图。

目标为统一、克制的商业化美术，不采用无约束的照片噪声堆砌。预绘制阴影需要在模型 360° 旋转时保持合理，不与简化的实时光照互相矛盾。

## 第一个验证资产：虎式坦克

验证流程为 **三视图 → 低多边形虎式坦克 → 精美贴图**，逐阶段验收；现阶段不预设具体开发 Issue，也不宣称样车已经完成。

重点检查虎式车体、炮塔、长炮管和履带的辨识度，并评估无需复杂骨骼即可完成炮塔转动、炮管后坐等刚性机械动作的可能性。优先在 64、128、256 像素级游戏视图中比较真实渲染效果。

**首个关键实验**：同一真实低模分别以无贴图和有贴图状态渲染，检验贴图能否显著提高观感，而不是依赖未经验证的精细几何图像。

## 预期资产组织

模型建成后建议按单个资产归档，以下只是约定，**当前不创建空目录或示例假文件**：

- `models/<资产标识>/references/`：三视图、尺寸来源、授权信息。
- `models/<资产标识>/source/`：Blender 源文件及可复现的建模、UV、烘焙脚本。
- `models/<资产标识>/textures/`：实际应用的贴图及必要源文件。
- `models/<资产标识>/export/`：通用模型交付文件，例如 GLB/FBX。
- `models/<资产标识>/preview/`：原始灰模、线框、多角度与 RTS 尺寸实际渲染截图。

每项资产应说明原始参考、制作工具、实际三角面数、贴图分辨率、尺寸/坐标约定、材质方案、可动部件以及限制。

## 开发与授权

- 默认开发与合并目标分支为 `dev`；未经明确授权不得改动 `main`。
- 所有制作结果都必须能通过真实文件、脚本或可复现渲染进行验证，不以 AI 生成的概念图冒充 Blender/Unity 的实际结果。
- 优先使用自制、明确允许改造与商业使用的源资产。第三方模型与贴图必须记录来源和许可，尤其注意 AI 输入、改作、再发布的限制。
- **仓库公开不等于所有模型可自由商用或再分发。** 各资产的版权和许可应单独标明；在明确设定前，不作开放许可承诺。
