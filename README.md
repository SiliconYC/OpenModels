# 开放模型仓库（OpenModels）

AI 辅助设计与制作的可复用游戏美术资产库：兼容真实三维模型与受控生成的多方向二维精灵图，供游戏、动画和可视化项目使用。

本仓库的目标不是展示漂亮但无法实现的概念图，而是**生产可追溯、可验证、可交付的商业级资产**：3D 管线交付真实几何、UV 和贴图；2D 管线交付受控绘制的多方向透明 PNG。

## 设计方向

- **商业化完成度**：造型、配色、比例、识别性和整体统一性必须达到成熟商业产品的标准；不把粗糙当成「独立风格」。
- **低多边形 + 高品质贴图**：以准确轮廓和主要机械体块为基础，把装甲接缝、编号、磨损等表面细节尽可能交给贴图；不堆砌无意义的几何。
- **面向小尺度显示**：优先以 RTS 中的小型单位为使用场景，同时保留必要的放大展示能力。不能只凭近景大图评价效果。
- **简化光照依赖**：优先研究无光照 / 自发光材质配合预绘制的风格化贴图；允许少量实时接地阴影。避免强烈烘焙方向高光与实时光照冲突。
- **可维护的批量生产**：优先采用授权合规的参考资料、手写网格或云端 Python 参数化生成、标准化源文件和可复现验收。修改现有资产通常优先于从零制作，但必须满足授权要求。
- **跨项目复用**：不绑定任何桌面建模器或游戏引擎；以代码/Python 源文件、真实 GLB/glTF 模型及贴图为交付，GitHub Pages 为唯一在线视觉验收入口。

首批重点研究坦克等刚性载具，后续可扩展汽车、飞机、舰船和其他模型。暂不为人物等需要复杂形变的角色预设统一生产工艺。

## 3D 资产制作流程

### 1. 三视图

建立同一尺度和比例下的正面、侧面、顶部正交参考图。标明车头方向、各轴向、主要尺寸比例及重要旋转中心。

三视图是几何参考，不是可以替代建模的视觉海报；若来自 AI 绘图，必须核查三个视图之间的结构是否一致。

### 2. 低多边形模型

依据三视图建立真实、可编辑的简化三维网格。先保证整体轮廓、机械体块、位置和转动轴正确，再控制面数。面数目标按照最终显示尺寸确定，不能仅凭概念图声称具体三角面数量。

刚性载具优先拆成车体、炮塔、炮管、车轮或螺旋桨等对象，用层级和枢轴控制；无实际必要不引入骨骼、蒙皮和复杂物理系统。

### 3. 精美贴图

为**实际模型的 UV** 制作高质量、设计化的贴图，尽量用色彩、接缝、表面磨损和局部明暗表达细节。允许 AI 绘图辅助，但最终纹理必须准确映射模型，不能把单张漂亮的效果图冒充成贴图。

目标为统一、克制的商业化美术，不采用无约束的照片噪声堆砌。预绘制阴影需要在模型 360° 旋转时保持合理，不与简化的实时光照互相矛盾。

## 第二条管线：N 方向二维精灵图

**完整规范：[standards/n-direction-sprites.md](standards/n-direction-sprites.md)**。这是一条与 3D + UV 平行的独立生产管线，目标是《突袭》类正交 RTS 的高质量透明 PNG，而不是完成精细 3D 模型。

**三视图 → 极简 3D 控制模型 → Python 固定正交相机批量输出轮廓/深度/部件遮罩 → 4×4 控制图 → AI 受控绘图小样 → 16 方向基准 → 32 → 64 → 透明 PNG 图集与在线旋转验收。**

- 虎式坦克首轮只做车体、炮塔和炮管**一体版**。炮塔分离、开火和后坐不在首轮范围。
- 以 64 个均匀方向为同一套索引，16 与 32 是其中的子集；相机、尺度、地面锚点始终固定。
- 4×4 拼图用于参考与验收，正式素材保留各方向**独立高解析度**文件，不强迫将成品一次画进低清图集。
- **有控制图不等于已真正运行 ControlNet；ControlNet 不保证跨方向细节一致。** 必须先小规模实证，失败就停止扩展；保存模型版本、参数、来源授权和失败案例。
- 共用三视图与工程数据，不依赖 Issue #19 精细 3D 完成，亦不要求 2D 路线做 UV。
- 新增跨资产工具 `tools/sprites/`、每资产 `sprites/`（控制图/候选/通过验收的 PNG/图集/质量证据），沿用 `docs/` 展厅，增加真实 PNG 播放、16/32/64 方向及 64/128/256 像素检视。这里只是规划，未声称已存在这些素材或工具。

## 第一个验证资产：虎式坦克

首条 3D 验证流程为 **三视图 → 低多边形虎式坦克 → 精美贴图**，原有 #3～#9 独立验收；第二条 N 方向 2D 管线独立建 Issue，共用参考但不混淆完成状态。

重点检查虎式车体、炮塔、长炮管和履带的辨识度，并评估无需复杂骨骼即可完成炮塔转动、炮管后坐等刚性机械动作的可能性。优先在 64、128、256 像素级游戏视图中比较真实渲染效果。

**首个关键实验**：同一真实低模在 GitHub Pages 查看器中分别以无贴图和有贴图状态渲染，检验贴图能否显著提高观感，而不是依赖未经验证的精细几何图像。

## 目录结构（规划）

以**资产为中心，自包含归档**；公共工具和规范在仓库根目录共享。以下是未来组织约定，**并非当前已经创建的目录**。

```text
OpenModels/
├── models/
│   ├── vehicles/
│   │   ├── land/
│   │   │   ├── tiger-i/
│   │   │   │   ├── asset.yaml
│   │   │   │   ├── references/
│   │   │   │   ├── source/
│   │   │   │   ├── sprites/      # N 方向 2D 资源（按需）
│   │   │   │   ├── textures/
│   │   │   │   ├── export/
│   │   │   │   └── preview/

├── tools/
├── standards/

```

### 资产目录职责

- `asset.yaml`：资产标识、型号、当前阶段、比例与坐标约定、源文件、三角面数、贴图规格、可动部件、外部素材来源和授权信息。数据未确认前标为待验证，**不编造测量结果**。
- `references/`：三视图、工程尺寸依据、授权的参考资料和设计记录。
- `source/`：手写网格/参数化 Python 源文件、建模、UV、贴图与 GLB/glTF 导出脚本；不依赖 `.blend`。
- `textures/`：UV 对应的贴图及必要的可编辑绘制源文件；同模型的不同涂装作为贴图变体管理，**不重复复制整套网格**。
- `sprites/`：N 方向图的控制图、AI 候选、验收 PNG、导出图集与质量报告；不与 3D UV 混用。
- `export/`：从源代码生成的可重新加载 GLB/glTF 和必要配套资源，与源代码区分。
- `preview/`：GitHub Pages 实际渲染的灰模、线框、贴图前后对照与 64 / 128 / 256 像素 RTS 视图。
- `docs/`：GitHub Pages 静态展厅及模型索引；直接加载真实 GLB/glTF，支持鼠标/触控旋转、平移、缩放、视角复位、正交观察以及线框/材质切换。
- `tools/`：跨资产复用的纯代码 / Python 建模、UV、纹理、网格统计、GLB/glTF 导出及索引工具。
- `standards/`：共享的美术、模型尺度、坐标轴、材质与文件交付规范。
- `tests/`：可复用的网格、UV、材质、方向、导出等自动化验收测试。

### 组织原则

1. 目录按**用途 → 载具环境 → 具体型号**组织；不要把所有资源平铺在仓库根部。
2. 每个资产应可独立制作、修改、验证和交付；不同 Agent 可以在不同资产目录内并行工作。
3. 共享工具只放 `tools/`，单型号生成脚本留在其 `source/`；避免复制多套公共工具。
4. 三视图、低模、贴图可分阶段提交；未完成的阶段在 `asset.yaml` 中明确标识。
5. **GitHub Pages 是必备基础设施。** #4 建立网页展厅，后续每个模型都要有可直接访问的交互展示页面；未确认部署成功，不得报告在线验收通过。
6. 模型和大纹理文件的体积达到需要时再评估 Git LFS；不盲目引入。
7. **按需创建真实目录和文件，不提前批量创建空目录、伪造模型或示例成果。**

## 强制工作模式：GitHub 纯云端

- **仅允许 GitHub 云端创建、修改、提交和验收资产**：不依赖桌面版 Codex、用户 PC、Blender（包括后台运行）、Unity 编辑器或任何本地 GUI 建模工具。Agent 可以使用可用的云端沙盒运行 Python，但所有可复现代码与正式产物必须写回 GitHub。
- **3D 模型及 2D 控制夹具**必须由**纯手写网格或 Python 程序化几何**生成。允许使用无需图形界面的 NumPy、trimesh、Pillow 等库；不得用 Python 仅包装 Blender 调用。必须保存真实顶点、三角面、层级、UV、贴图和导出的 GLB/glTF。
- 无光照优先采用 glTF 标准 `KHR_materials_unlit` 或网页端可明确复现的等效材质方案；贴图须实际映射到模型 UV。
- **GitHub Pages 提供唯一正式在线验收环境**，目标网址为 `https://siliconyc.github.io/OpenModels/`。静态站点源优先使用 `dev` 分支 `/docs`；首次部署/分支来源若需仓库管理员设置，必须报告明确操作，不得虚称已上线。
- 每个完成的 **3D 模型**必须能通过网页查看器**自由旋转、平移、缩放和复位**，并提供正交观察、线框与贴图检查、机械部件分离或动作检验。展示对象是可交互的真实模型，而非截图轮播、伪 3D 或方向图动画。
- 采用 Three.js 等浏览器 WebGL 技术制作静态查看器，不要求后台服务器、桌面软件或重复运行大型 GitHub Actions 工作流。以实际公网 URL、版本提交、浏览器运行结果作为交付证据；Pages 未启用须如实说明。

## 开发与授权

- 默认开发与合并目标分支为 `dev`；未经明确授权不得改动 `main`。
- 所有制作结果都必须能通过真实文件、脚本或可复现渲染进行验证，不以 AI 生成的概念图冒充真实网格、UV、GitHub Pages 交互页面或在线渲染结果。
- 优先使用自制、明确允许改造与商业使用的源资产。第三方模型与贴图必须记录来源和许可，尤其注意 AI 输入、改作、再发布的限制。
- **仓库公开不等于所有模型可自由商用或再分发。** 各资产的版权和许可应单独标明；在明确设定前，不作开放许可承诺。

Agent 的执行细则见 [AGENTS.md](AGENTS.md)。
