# #24 最終幾何控制驗收（2026-10-17）

此報告僅評估真正從 #23 三角形網格輸出的**正交控制條件**，不屬正式 AI 美術驗收。

## 實際實物

- 單檔控制圖：全局 **000 至 063 共 64 槽**，每槽 silhouette（RGBA）、depth（16 位灰階）、parts（RGBA）各一張，合計 **192 張 512×512 PNG**，已全部提交在 control/frames/ 中。不存在佔位、靜態複製或以舊 GLB 當 N 方向 PNG。
- 四套真正 4×4 拼圖：canonical-16-{silhouette,depth,parts}.png + arbitrary-16-parts.png；每張均有 JSON 對應單格來源，任意方向測試用了 1,3,...31 共 16 個非預設槽。
- control/manifest.json：每一槽有 i×5.625°、三通道位置／SHA-256／可見部件／深度範圍；固定 spec、模型 SHA、正交相機、pivot。可用檔位經物理檔案驗證為 **[16,32,64]**。
- 固定相機方位 45°、俯角 35°；512×512、47px/m、pivot [256,354]；車身繞 +Y 旋轉而相機不動。鏡頭 Z-buffer 插值深度是真正三角形可見深度，而非 8 位表面亮度。

## 測試

- 真實來源構建、模型比例與十向正交 QA：見已合併 #23 PR #35。
- 全量 image decode、mask/depth alpha 前景一致、16-bit PNG、不重複輪廓、嚴格 SHA、16/32/64 槽號，全部由生成作業及專用單元測試驗證。
- 64 個相鄰方向（包含 **063→000 跨界**）使用 alpha 輪廓交並比測試，排除異常跳幀；結果以最新 CI 為準。
- 4×4 順序行優先，單格 256px，結果索引與所選全局方向對照驗證。
- 生成期間**未修改** docs、sprite 頁面、models.json、既有 GLB、main 或正式 approved/export 美術。

## 視覺審核與不確定性

真實拼圖確認一周旋轉方向連續、履帶/砲塔/砲口方位跨角度可辨、尺度固定，但以 512px 控制條件而言，細齒與小結構未完整呈現。

**已知不足**：早期橡膠輪是簡化 12 節面圓柱；履帶塊、車輪輪轂與制退器孔洞被略去，砲盾精密非對稱鑄件仍屬近似；前視、側視的高細節輪廓尚須由正式三視圖及已核准風格基準協助 AI。這些不是 bug 掩飾，也不能宣稱完整 CAD 或商業美術合格。

**#25 前置判定：技術上可開始小樣實驗**，因為 64 槽三通道完整輸出，AI Agent 可直接使用單張控制圖。真正 AI 模型的控制遵從性、跨方向貼圖連續性、授權與商業完成度**未驗證**，應只在 #25 嘗試 4–8 向受控對照後再決策，嚴禁把本 Issue 當成 AI 美術已完成。
