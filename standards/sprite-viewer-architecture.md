# OpenModels GitHub Pages 双入口与 N 方向图播放器架构

状态：实施前的**正式架构契约**。OpenModels 今后的**唯一重点生产路线**是 AI 受控 N 方向二维精灵图（下称“伪 3D”）。旧的 3D + UV + 精细贴图路线已因视觉效果不达要求而**停止作为主线开发**；既有 GLB、Python 源码、三视图、UV 与在线 3D 查看能力继续保留，用于参考、兼容与必要验收。**不要删除或篡改旧 3D 成果，也不要为新方向图强行开发精细 3D 贴图。**

实施由独立的「Pages 双入口与伪 3D 播放基础设施」Issue 负责，**必须可以在正式 AI 图片出现之前完成并验收**。后续 AI 内容生产仍按 [N 方向图生产规范](n-direction-sprites.md)。

## 1. 站点信息架构

发布源仍是 `dev:/docs`，不改 Pages 设置，也不改 `main`。本站为**纯静态网站**，不依赖后台、打包服务器或本机 GUI。

- `/OpenModels/` → **双入口首页**，展现两个清楚可辨的入口：
  - **多方向图／伪 3D（主线）** → `/OpenModels/sprites.html`：N 方向资产目录、状态与统一的图片播放器。优先显示为主入口，但未有正式资产时明确显示“尚未发布正式方向图”，禁止冒充已完成。
  - **传统 3D（保留）** → `/OpenModels/3d.html`：原有 Three.js GLB 真实交互展厅、所有控件与资产不丢失，标识为“历史成果／辅助参考”；**不把旧 3D 模型称为最终商业级资产**。
- 兼容历史 `/OpenModels/?model=...`、`/OpenModels/docs/?model=...` 等链接：旧的 `model` 参数应正确进入原 3D 视图且保留参数，不能把旧模型选择误送往 PNG 播放器。原根目录兼容 `index.html` 若属于非 Pages 生效范围，也要保持合理重定向逻辑。
- 新方向图深链：`/OpenModels/sprites.html?asset=tiger-i&variant=integrated&level=16&heading=0`。无效查询参数要安全回退到目录或提示；不能从查询字符串拼任意图片 URL。旧 3D 的 `model` 命名空间不得被重新解释为 N 方向图。
- 保留清晰的回首页与两专区互达导航，不要把展示页面做成工程控制台、杂乱无意义标签或复杂 Dashboard。PC/移动端均要可访问，优先简洁的商业级视觉秩序。

上述文件名为**首版明确建议**，允许 Agent 有充分理由调整内部文件组织，但**公开路径、兼容性与语义不得任意改变**，需文档说明。

## 2. 通用数据模型：每个项目同一个契约，不写逐车型页面

源仓库仍以资产为中心，类型不同也复用一致布局：

`models/vehicles/land/<asset-id>/sprites/`：
- `spec.json`：生产参数唯一真源（模型/相机/方向、锚点、颜色规范），符合 [N 方向图生产规范](n-direction-sprites.md)。
- `control/`、`generated/`、`approved/`、`qa/`：生产与审核中间资料，只随需要创建。
- `export/manifest.json`：由最终核准的 `approved/` 和 `spec.json` **自动导出**的运行时索引，记录来源、文件与发布档位。
- `export/frames/000.png` 至 `063.png`：**按全局 64 槽编号**的独立 RGBA PNG。只发布真正存在且批准的帧；16 向首批仅有 `000.png, 004.png, …, 060.png`，32 向再增加 `002.png, 006.png, …, 062.png`；64 向补奇数帧。命名固定三位数，禁止每档重编号 `0..15` 或按人为视觉顺序临时调换。
- `export/atlases/`：**可选**的实际游戏发布图集及对应映射索引，不是网页播放依赖；4×4 AI 控制拼图只属于生产/审核，不当成逐帧播放源。

**重要部署事实**：GitHub Pages 选择 `dev:/docs` 时，仓库中 `models/` 下的文件不会自动公开在站点根 URL。因此发布流程必须把**经过批准的** `export/` 所需文件**复制/构建到** `docs/assets/sprites/<asset-id>/<variant>/` 并写入 `docs/sprites-catalog.json`；不要求网页直接访问 `../models/`。镜像的 SHA/清单与源文件一致，禁止人工改动发布副本导致源与部署漂移。只有真正可用的发布数据才能进入可播放列表；“计划中”资产可以显示在目录，但必须明确不可播放。

不同项目共享同一个目录结构、同一组导出命名和同一播放器；`tiger-i` 仅作为首个真实样品，不在 JS/HTML 写死它。下一辆车只添加 manifest + 文件并更新目录索引，**不复制一份播放器或写新的 64 次硬编码**。

## 3. manifest v1：最小稳定字段

`manifest.json` 为受版本控制、可校验的 JSON，下面是**规范示意而非已生成文件**。帧文件键以三位全局索引命名，其余不完整帧在实际文件里不得伪造。

```json
{
  "schema_version": 1,
  "asset_id": "tiger-i",
  "variant": "integrated",
  "release_status": "approved",
  "title": "Tiger I — 一体化",
  "heading_slots": 64,
  "zero_heading": "forward +X; locked in spec.json",
  "positive_rotation": "+Y",
  "degrees_per_slot": 5.625,
  "canvas": { "width": 1024, "height": 1024, "color_space": "sRGB", "alpha": "straight" },
  "pivot_px": [512, 840],
  "available_levels": [16],
  "frames": {
    "000": "frames/000.png",
    "004": "frames/004.png"
  }
}
```

上例仅示意字段格式，**不是通过验证的完整 16 帧发布清单**：若声称 `available_levels: [16]`，实际清单必须完整具备 16 个索引，不能只发布两帧。实现中应使用满足该约束的完整测试数据；缺失时应拒绝声明该档可用。

- `asset_id` + `variant` 是身份，未来可扩展 `turret`、`hull`、`state`，但**首轮只允许整车一体版 `integrated`**；未来分层/后坐/开火另立协议，禁止提前扩大组合维数。
- `heading_slots = 64` 是全局唯一离散环；可播放档位 `16`、`32`、`64` 对应槽 `step=64/level`，期望索引 `0,step,…,63`。**任一档位仅在全部对应帧齐全、真实可解码且已批准时方可宣布 available**。其他索引可以不存在，不能自动用临近角度补图/镜像/插值冒充。
- 角度计算由索引 + 锁定的 `zero_heading` 和 `positive_rotation` 约定推导；不要在每帧手工填写可能冲突的旋转角度。实际相机俯角、scale、模型原点等仍以 `spec.json` 和生成记录为准。
- `canvas`、`pivot_px` 统一所有方向，网页按 **pivot 坐标**对齐到固定画布地面投影点，不能逐帧根据 alpha 包围盒自适应放大或居中，防止旋转“跳舞”。
- `frames` 是白名单映射，只能引用发布 manifest 所在目录之下的相对 PNG 路径；校验禁止 `../`、根路径、外部 URL 与重定向式资源注入。运行时不可用的帧应报错并阻止虚假完整播放。
- `release_status` 至少区分 `fixture` / `approved`。**仅 `approved` 才可视为正式美术资产**；测试夹具不能在主页装成正式虎式坦克。
- 正式资产还应能追踪 `spec` 版本、生成来源 SHA、批准审查状态、版权/商业授权和发布对应 SHA；可在 manifest 中添加 `source_revision`、`license` 等字段，不得捏造许可证。

`docs/sprites-catalog.json` 作为纯静态全局目录：仅用于列出资产、类型、是否可播放、manifest 相对路径（或友好的“计划中”状态）；**不复制 64 份逐帧路径**，播放数据以各资产 manifest 为唯一真源。

## 4. 通用播放器和渲染架构

- **不用 Three.js 模拟 3D**；伪 3D 播放器本质是 Canvas 2D 或单张 `<img>`/CSS 的 RGBA 帧替换器。共享 `docs/sprites-viewer.js` 一套引擎，数据驱动按 manifest 切换模型；3D 展厅继续独立加载 Three.js，避免让首页和 2D 路由为了展示 PNG 加载庞大 3D 包。
- 用固定大小逻辑舞台、统一缩放与锚点，不对每张图单独 `object-fit: contain` 后居中。显示尺寸提供实际 `64/128/256` 像素 RTS 检查和放大查看；透明背景检验可切换纯色/棋盘预览，棋盘只属于网页画布。
- 交互：前一方向／后一方向、拖拽水平或触屏滑动转向、自动循环/暂停、16/32/64 可用档位切换、角度/索引指示。**只有真实已批准的整档可用才允许播放该档位**，控制须有功能而不是装饰。
- 可按需**先缓存当前位置及临近帧**，有空闲资源再预载其他帧；浏览器不应因几十张高清 PNG 一次全尺寸解码导致低端设备卡死。坏文件、404、网络错误应产生明确状态，不能自动显示上一帧后仍标成已转向。
- 同方向纹理/涂装等未来变体可以由不同 manifest 区分，播放器无需写车型例外。未来分体只需在扩展协议中声明图层/pivot/遮挡排序，但**不在当前基础设施做不存在的动画组合**。

## 5. 先于正式美术的工程验收

基础设施任务**不依赖 #23–#28 的 AI 美术进度**，应立即完成：

1. 保留既有 3D 展厅所有 GLB 加载、正交/透视、鼠标/触控与部件控制，在新双入口下重新验证。
2. 部署真正的双入口首页，PC 和移动端两边均能进入；旧链接无回归，`/OpenModels/` 不能直接跳进 3D。
3. 制作**明确标记“测试夹具（非虎式成品）”的程序化透明 RGBA 帧**，例如明显编号的几何方向箭头，至少完整覆盖 16 槽并最好 64 槽，以测试方向和锚点；保留脚本与测试清单。此举是**播放器验证**，不能当成 AI 方向资产验收。正式目录不可把测试夹具与正式美术混淆。
4. 对一份测试 manifest 实际验证多档位、顺逆转、零到最后一帧连接、查询参数、pivot 固定、透明背景、画面尺寸与异常 URL/缺帧处理，保证所有控件真实可用。
5. 用实际公网 GitHub Pages URLs + 无头 Chrome 真正载入、切换、滑动、缩放/切档（若适用），桌面和手机视口截图与 HTTP 结果双重核验，注明提交 SHA 和未验证项；测试不应虚报人工商业美术质量。
6. CI 精简并做过时运行自动取消；单次 PR 必须对最新 HEAD 做必要测试，部署之后公网冒烟测试须核验**真实页面和图片**，不是仓库 README。
7. 最终用户从首页进入“多方向图”应看到完成的播放器基础设施和**明确的尚无正式素材状态**；不能用精细灰模或图片拼贴营造已发布资产的错觉。
